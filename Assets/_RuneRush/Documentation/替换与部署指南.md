# 符文疾驰：场景替换与部署指南

本指南面向后续替换赛道、完整西式奇幻场景、车辆、障碍和第一人称座舱的制作人员。项目把比赛规则与美术对象解耦：赛道控制点、静态环境和赛事布局都可以在 Unity 的 Scene 窗口持久编辑；运行时只读取已保存的赛道和布局数据。

## 先理解场景结构

打开 [`RuneRushRace.unity`](../Scenes/RuneRushRace.unity) 后，保留以下对象和组件：

| 场景对象 | 必须保留的内容 | 用途 |
| --- | --- | --- |
| `RuneRush Game Runtime` | `RuneRushGame` | 启动赛事、输入、UI、音频与显示同步。 |
| `Track Authoring - Replace Control Points` | `RuneRushTrackAuthoring` 和有序控制点 | 逻辑赛道、圈数、AI 及全部赛道位置的来源。 |
| `Scene Bindings - Replace Prefabs Here` | `RuneRushSceneBindings`、Art Profile 引用和下列子根 | 静态场景、赛事标记与运行时生成物的分界。 |
| `XR Origin (PICO)` | `XROrigin`、`PXR_Manager`、`Camera Offset`、`Main Camera`、`TrackedPoseDriver` | PICO 头部视角与 XR 相机。 |

不要删除 `Main Camera` 的 `MainCamera` Tag，也不要另建第二台主相机。PICO 模式下，头显姿态直接驱动这台相机；桌面模式下它由赛车镜头定位。

`Scene Bindings - Replace Prefabs Here` 的子对象有明确职责：

| 子根 | 是否会保存／参与构建 | 正确用途 |
| --- | --- | --- |
| `AUTHORED ENVIRONMENT - Put Editable Models Here` | 会保存；比赛运行时不清除 | 地形、城堡、建筑、道路网格、树木、灯光和静态布景。 |
| `RACE LAYOUT - Editable Markers` | 会保存；位置同步为规则布局 | 拾取物、障碍和增益板的可视化位置标记。 |
| `EnvironmentRoot` | 运行时创建内容 | 程序化道路、环境与 Environment Prefab 实例；不要手工放需要保留的对象。 |
| `RaceObjectRoot` | 运行时创建内容 | 运行时拾取物、障碍、增益板和地雷；不要手工放需要保留的对象。 |
| `RacerRoot` | 运行时创建内容 | 玩家和 AI 赛车；不要手工放需要保留的对象。 |

## Unity Scene 直接编辑工作流

### 直接编辑完整样例场景

当前 `RuneRushRace` 已烘焙可持久编辑的西式奇幻样例环境。展开：

```text
AUTHORED ENVIRONMENT - Put Editable Models Here
└─ BAKED SAMPLE ENVIRONMENT - Edit or Replace
   ├─ CUSTOM CONTENT - Safe From Rebuild
   └─ GENERATED SAMPLE GEOMETRY - Rebuildable
      ├─ Royal Road / Stone Shoulders / Guardrails
      ├─ Race Gates / Forest / Watchtowers / Mountains
      └─ Crown Keep / Moon / Lighting
```

`GENERATED SAMPLE GEOMETRY` 下的道路分段、树木、塔楼、城堡、山体和灯光都是普通场景 GameObject，可在 Hierarchy 和 Scene 中直接选中、移动、删除或替换。自己的场景模型放入 `CUSTOM CONTENT - Safe From Rebuild`；它不会被重建操作删除。

选中 `Scene Bindings - Replace Prefabs Here` 后，`Bake Editable Sample Environment` 会按当前逻辑赛道重建样例实体，`Frame Baked Sample` 会在 Scene 中框选全景，`Clear Baked Sample Geometry (Keep Custom Content)` 只清除工具生成的部分。烘焙标记会让运行时跳过重复的程序化道路、环境和灯光。

### 第一次建立可编辑布局

当前默认布局包含 `12` 个拾取物、`18` 个障碍和 `5` 个增益板。若打开场景时没有 `RACE LAYOUT - Editable Markers` 或其中没有标记：

1. 执行 Unity 菜单 `Rune Rush > Scene Editing > Create Default Editable Layout`。
2. 在 Hierarchy 展开 `Scene Bindings - Replace Prefabs Here > RACE LAYOUT - Editable Markers`。
3. 按 `Cmd+S`（Windows 为 `Ctrl+S`）保存场景。保存钩子会把每个标记的位置写入 `RuneRushSceneBindings.Layout`。

该菜单会先清空已有赛事标记再生成默认布局，因此不要把它当作普通刷新按钮。需要恢复默认布局时先备份场景，或利用 Unity 的 Undo。

### 改赛道走线与道路预览

1. 在 Hierarchy 中选中 `Track Authoring - Replace Control Points`。
2. Inspector 的 `Focus` 会框选完整赛道；`Refresh Preview` 会生成蓝色道路／路肩预览和编号控制点，方便在 Scene 窗口定位。
3. 直接拖动 `Track Point 01...` 的编号手柄，或在 Hierarchy 中选中控制点再移动。`Control Points (race order)` 数组的顺序就是行驶方向。
4. 需要增加弯道时可使用 `Add Point`；它会在当前选中控制点之后插入，未选中时插在闭环接缝之前。
5. 保持 `Closed` 启用，且至少保留 4 个有效控制点；完成后保存场景。

道路预览使用编辑器临时对象，**不会保存到场景，也不会进入构建**。它只用来显示逻辑赛道和道路宽度；你的正式道路模型应放在 `AUTHORED ENVIRONMENT` 下。赛道重塑后，检查所有赛事标记，再执行 `Synchronize Markers → Layout` 或保存场景，使其重新投影到新道路。

### 摆放拾取物、障碍和增益板

选中 `Scene Bindings - Replace Prefabs Here` 后，Inspector 提供以下操作：

| 操作 | 结果 |
| --- | --- |
| `Add Pickup`／`Add Obstacle`／`Add Boost Pad`／`Add Repair Pad` | 在赛道上创建一个新的持久标记，并立刻同步布局。 |
| `Synchronize Markers → Layout` | 将全部标记的位置、车道偏移、障碍类型和增益板类型写入运行时布局。 |
| `Frame Editable Content` | 在 Scene 窗口框选静态环境根和赛事标记根。 |
| `Clear Race Markers` | 删除全部赛事标记并清空对应布局；Unity 会先显示确认框，可立即 Undo。 |

每个标记根对象都带有 `RuneRushRaceLayoutMarker`。保留该组件，然后按下列方式编辑：

1. 在 Scene 窗口移动标记根对象；自定义 Position Handle 会记录其赛道进度与横向车道。
2. 在 Inspector 调整 `Kind`。障碍同时可设置 `Obstacle Kind`（石箱、路障、油沼、旋转横杆、闸门）；增益板可设置 `Pad Kind`（加速／维修）。
3. 在根对象下删除或替换 `EDITOR VISUAL - Replace With Your Model` 子物体，以便用自己的模型准确看见场景位置、大小和朝向。
4. 保存场景，或点击 `Synchronize Markers → Layout`。同步会把标记投影到最近的逻辑赛道，并将横向位置限制在约 `±9m` 的可行驶范围。

可以复制标记根对象来增加同类玩法，或删除它来移除玩法。运行时按标记数据生成对应物件：某一类一个标记都没有时，该类会回退到原始默认布局；该类保留一个或更多标记时，则只使用这些已保存标记。

标记子模型用于场景编辑时的可见参照，**不会指定运行时动态 Prefab**。若要让比赛中生成的物件也替换为自己的模型，请同时在 Art Profile 的 `Race Objects` 槽位设置对应 Prefab。

### 放置完整静态环境和灯光

1. 导入自己的地形、城堡、树木、关卡门、天空布景和灯光。
2. 直接把这些对象拖入 `AUTHORED ENVIRONMENT - Put Editable Models Here` 下，随后就能像普通 Unity 场景一样移动、复制、删除、分组或加组件。
3. 若自制环境已有道路、护栏和关卡门，在 [`RuneRushArtProfile.asset`](../Settings/RuneRushArtProfile.asset) 中关闭 `Generate Procedural Track`。
4. 若自制环境已包含完整地形与布景，关闭 `Generate Procedural Environment`；必要时关闭 `Use Procedural Fallback`，避免缺失槽位时叠加默认占位物。
5. 若场景使用自己的 Directional Light、雾效或后续烘焙灯光，关闭 `Override Scene Lighting`，避免比赛启动时覆盖你的场景照明。
6. 保存场景后按 Play，检查道路与逻辑赛道对齐、车辆尺度、地面高度和 HUD 可读性。

即使关闭程序化道路，也必须保留 `RuneRushTrackAuthoring`：它是比赛逻辑坐标系，而不是道路网格。自制道路应沿控制点方向布置，尤其应确保起点附近与逻辑赛道对齐。

## Prefab 与视觉替换

### 动态赛车与第一人称座舱

在 Art Profile 的 `Vehicles` 区指定：

| 槽位 | 用途 | 建议 Prefab 约定 |
| --- | --- | --- |
| `Player Vehicle` | 玩家赛车的外部模型 | Prefab 根节点的 **+Z 为前方**，地面位于本地 Y=0 附近。 |
| `Ai Vehicle` | 5 名 AI 的外部模型 | 同样以 +Z 为前方；可使用同一 Prefab。 |
| `Cockpit` | 固定在第一人称相机 Rig 下的座舱 | Prefab 根节点本地位置／旋转保持 0；模型应置于镜头下方及前方，避免遮住中心视野。 |

以下命名为推荐接口，而非强制组件：

- `VisualSlot`：赛车外观根；存在时会获得转向侧倾。
- `Wheel_*`：作为 `VisualSlot` 的直接子物体时会随速度旋转。
- `ShieldVfxAnchor`、`TailVfxAnchor`：护盾和增压尾迹锚点；缺失时运行时会创建默认锚点。
- `MotionRoot`：旋转障碍的可动部分；没有该节点仍会参与规则判定，只是不播放该局部旋转。

### 拾取物、障碍与增益板

在 Art Profile 的 `Race Objects` 区替换下列运行时视觉 Prefab：

| 槽位 | 对应玩法 |
| --- | --- |
| `Pickup`、`Mine` | 圣物拾取物、玩家／AI 放置的诅咒石。 |
| `Boost Pad`、`Repair Pad` | 加速符文板、维修／治疗板。 |
| `Crate`、`Barricade`、`Oil`、`Spinner`、`Gate` | 石箱、路障、油沼、旋转横杆、闸门。 |

Prefab 根节点宜位于局部原点、以 +Z 为前。规则碰撞使用赛道距离判定，不依赖模型 Collider；可以为自己的交互添加 Collider，但它不会替代比赛规则判定。

## 保存、重新生成与 PICO 构建

### 保存规则

`Cmd+S`／`Ctrl+S` 保存 `RuneRushRace.unity` 时，编辑器会把 `RACE LAYOUT - Editable Markers` 中的全部标记同步到 `RuneRushSceneBindings.Layout`。这一步决定实际比赛里拾取物、障碍和增益板的数量、类型与位置。

建议的修改循环是：**移动控制点／模型或标记 → 同步或保存 → Play 检查 → 保存**。移动标记后不要只依赖未保存的 Scene 视图状态；构建和重新打开场景只会读取已保存内容。

### 哪些菜单安全，哪些会重建场景

| 操作 | 是否覆盖已保存的手工场景 | 说明 |
| --- | --- | --- |
| `Rune Rush > Project > Create or Refresh Race Scene` | 会覆盖 | 新建默认场景、控制点和绑定；仅用于明确重置项目。先复制场景备份。 |
| `Rune Rush > Scene Editing > Create Default Editable Layout` | 会覆盖赛事标记 | 不覆盖静态环境，但会删除并重建全部拾取物／障碍／增益板标记。 |
| `Rune Rush > PICO > Configure Android Project` | 不会覆盖已有场景 | 只有 `RuneRushRace.unity` 不存在时才创建示例场景。 |
| `Rune Rush > PICO > Build Android APK` | 不会覆盖已有场景 | 会先执行上述安全的 PICO 配置，再构建当前已保存场景。 |
| Unity 标准 Android Build Profiles／Build Settings | 不会覆盖已有场景 | 同样会读取当前已保存的 Build Settings 场景。 |

因此，完成场景编辑后可以直接使用 PICO 菜单构建，不必为了保护布局而改走其他构建流程；关键是先保存场景。仍建议在大范围重构前复制 `RuneRushRace.unity` 作为关卡备份。

## 控制说明

### 桌面键盘

| 操作 | 按键 |
| --- | --- |
| 转向／油门／刹车 | `A`/`D` 或方向键左/右；`W` 或上；`S` 或下 |
| 漂移／氮气／使用圣物 | `Space`；`Shift`；`E` 或 `Enter` |
| 复位／暂停 | `R`；`Esc` 或 `P` |
| 菜单难度与确认 | 左/右方向切换；`Enter` 或 `Space` 确认 |
| 暂停页 | `Enter`／`Space` 继续；`Backspace` 重开 |
| 结算页 | `Enter`／`Space` 再来一局；`Backspace` 返回赛事台 |

### 手柄与 PICO 控制器

| 操作 | 通用手柄 | PICO 控制器 |
| --- | --- | --- |
| 转向 | 左摇杆 X | 左手摇杆 X |
| 油门／刹车 | 右扳机或南键／左扳机或东键 | 右扳机／左扳机 |
| 漂移／氮气 | 西键／左肩键 | 左手主键／右手握把键 |
| 使用圣物 | 右肩键 | 右手主键 |
| 复位／暂停 | 北键／Start | 左或右手副键／左手 Menu |
| 菜单确认 | 南键 | 右手主键 |

在 PICO 的赛事台，左手摇杆左右切换难度，右手主键开始。暂停时右手主键继续、右手副键重开；结算时右手主键再来一局、右手副键返回赛事台。头部转动仅改变视角，不改变赛车方向。

## PICO Android 构建

项目当前配置目标为 Android、IL2CPP、ARM64、最低 API 29、Vulkan、PICO XR Loader、Multiview 与 URP HDR 关闭。

1. 在 Unity 打开项目，等待 PICO XR `0.13.1` 解析完成。
2. 保存场景后，执行 `Rune Rush > PICO > Configure Android Project`，再执行 `Rune Rush > PICO > Validate Android Project`。Console 出现 `RUNE_RUSH_PICO_VALIDATE_OK` 表示配置校验通过。
3. 执行 `Rune Rush > PICO > Build Android APK`；预期输出路径为 `Builds/PICO/RuneRushCrownCup.apk`。该操作会保留当前已保存场景。
4. 本地调试签名位于 `BuildArtifacts/Signing/runerush-dev.keystore`。正式发布前替换为自己的签名证书，并重新检查包名 `com.runerush.crowncup`、版本号和商店要求。

配置校验和 APK 构建成功不等于头显运行验收。发布前仍应完成 PICO Emulator／真机安装启动、控制器输入、画面舒适度、日志和性能的实际检查。
